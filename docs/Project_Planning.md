# Campus Resource Management System
## Project Planning Document

### 1. Project Objective
To develop a centralized system through which campus users can view available resources, request bookings and manage their booking activities.

### 2. Project Scope
- Student and faculty registration
- Secure login
- Resource listing
- Booking creation and cancellation
- Booking history
- Administrator functions
- Incident reporting
- Notifications

### 3. Team and Responsibilities
The project uses collaborative development with separate frontend, backend, database and administration responsibilities. Individual member contributions should be recorded according to actual work performed.

### 4. Development Phases
1. Requirement analysis
2. Database design
3. Backend API development
4. Frontend development
5. API integration
6. Unit and integration testing
7. Documentation
8. Final demonstration

### 5. Tools
- Git and GitHub for version control
- React and Vite for frontend
- Flask and Python for backend
- PostgreSQL for database
- Pytest for backend testing

### 6. Risks and Mitigation
| Risk | Mitigation |
| API integration issues | Verify endpoints and request formats |
| Database connection errors | Validate environment configuration |
| Authentication errors | Test JWT and protected routes |
| Booking conflicts | Validate date and time overlap |
| Merge conflicts | Use branches and review changes |

### 7. Deliverables
- Source code repository
- Database schema and seed data
- Frontend application
- Backend REST API
- Test plan and test evidence
- Architecture documentation
- UML use case diagram
- Final demonstration

### 8. Completion Criteria
The application should build successfully, backend tests should pass, database connectivity should work, and the frontend should demonstrate actual API communication.
